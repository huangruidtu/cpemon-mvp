# acs-ingest Kafka Producer Integration Validation

## Purpose

This runbook proves the live path:

```text
ACS webhook payload -> acs-ingest -> EventPublisher -> Kafka topic -> Kafka consumer
```

Unit tests prove schema mapping and producer behavior without Kafka. This
runbook proves the broker-facing integration path when a Kubernetes cluster and
Kafka release are available.

## Preconditions

Required tools:

* `go`
* `helm`
* `kubectl`

Required platform state:

* CPEmon app namespace: `cpemon`
* Kafka namespace: `kafka`
* Kafka bootstrap service: `kafka.kafka.svc.cluster.local:9092`
* Topics:
  * `cpemon.device.heartbeat.v1`
  * `cpemon.wan.status.v1`

Repository checks before live validation:

```powershell
go test ./...
helm lint deploy/helm/cpemon -f deploy/helm/cpemon/values-dev.yaml
helm template cpemon deploy/helm/cpemon -n cpemon -f deploy/helm/cpemon/values-dev.yaml
```

## Enable Producer

Render or deploy with:

```yaml
appConfig:
  kafkaProducerEnabled: true
  kafkaBootstrapServers: kafka.kafka.svc.cluster.local:9092
  kafkaTopicDeviceHeartbeat: cpemon.device.heartbeat.v1
  kafkaTopicWanStatus: cpemon.wan.status.v1
  kafkaProducerTimeout: 5s
  kafkaProducerMaxRetries: 3
```

Expected `acs-ingest` environment variables:

```text
KAFKA_PRODUCER_ENABLED=true
KAFKA_BOOTSTRAP_SERVERS=kafka.kafka.svc.cluster.local:9092
KAFKA_TOPIC_DEVICE_HEARTBEAT=cpemon.device.heartbeat.v1
KAFKA_TOPIC_WAN_STATUS=cpemon.wan.status.v1
KAFKA_PRODUCER_TIMEOUT=5s
KAFKA_PRODUCER_MAX_RETRIES=3
```

## Start Consumers

Heartbeat topic:

```powershell
kubectl exec -n kafka statefulset/kafka-controller -- kafka-console-consumer.sh `
  --bootstrap-server kafka.kafka.svc.cluster.local:9092 `
  --topic cpemon.device.heartbeat.v1 `
  --from-beginning `
  --property print.key=true `
  --property key.separator="|" `
  --max-messages 1
```

WAN status topic:

```powershell
kubectl exec -n kafka statefulset/kafka-controller -- kafka-console-consumer.sh `
  --bootstrap-server kafka.kafka.svc.cluster.local:9092 `
  --topic cpemon.wan.status.v1 `
  --from-beginning `
  --property print.key=true `
  --property key.separator="|" `
  --max-messages 1
```

## Send ACS Payload

Port-forward `acs-ingest`:

```powershell
kubectl port-forward -n cpemon svc/acs-ingest 8080:8080
```

Send a payload that should create both heartbeat and WAN status events:

```powershell
$payload = @{
  sn = "TEST-CPE-0001"
  event_ts = "2026-06-21T10:30:00Z"
  wan_status = "up"
  wan_ip = "10.0.0.13"
  sw_version = "v1.0-demo"
} | ConvertTo-Json -Compress

Invoke-RestMethod `
  -Method Post `
  -Uri "http://127.0.0.1:8080/acs/webhook" `
  -ContentType "application/json" `
  -Body $payload
```

Expected HTTP response:

```json
{"status":"queued"}
```

## Expected Kafka Output

Heartbeat consumer should show key `TEST-CPE-0001` and a JSON payload like:

```json
{
  "schema_version": "v1",
  "event_type": "device.heartbeat",
  "source": "acs",
  "device_id": "TEST-CPE-0001",
  "serial_number": "TEST-CPE-0001",
  "event_ts": "2026-06-21T10:30:00Z",
  "status": "online"
}
```

WAN status consumer should show key `TEST-CPE-0001` and a JSON payload like:

```json
{
  "schema_version": "v1",
  "event_type": "wan.status",
  "source": "acs",
  "device_id": "TEST-CPE-0001",
  "serial_number": "TEST-CPE-0001",
  "event_ts": "2026-06-21T10:30:00Z",
  "wan_status": "up",
  "wan_ip": "10.0.0.13",
  "sw_version": "v1.0-demo"
}
```

`received_at` is generated by `acs-ingest`, so it should be present but will
not equal the fixed input timestamp.

## Logs And Metrics Evidence

Expected producer success logs:

```text
event=kafka_publish result=success topic=cpemon.device.heartbeat.v1 key=TEST-CPE-0001
event=kafka_publish result=success topic=cpemon.wan.status.v1 key=TEST-CPE-0001
```

Expected metrics:

```text
acs_ingest_kafka_producer_publishes_total{topic="cpemon.device.heartbeat.v1",result="success"}
acs_ingest_kafka_producer_publishes_total{topic="cpemon.wan.status.v1",result="success"}
acs_ingest_kafka_producer_publish_duration_seconds_bucket{topic="cpemon.device.heartbeat.v1",result="success",le="..."}
acs_ingest_kafka_producer_publish_duration_seconds_bucket{topic="cpemon.wan.status.v1",result="success",le="..."}
```

Inspect metrics:

```powershell
kubectl port-forward -n cpemon svc/acs-ingest 9100:9100
Invoke-WebRequest http://127.0.0.1:9100/metrics | Select-Object -ExpandProperty Content
```

## Failure Drill

If the consumer receives no message:

1. Confirm `KAFKA_PRODUCER_ENABLED=true` in the `acs-ingest` pod.
2. Confirm topics exist with `kafka-topics.sh --list`.
3. Check logs for `event=kafka_publish result=error`.
4. Inspect error `kind`, `topic`, `key`, `attempts`, and `duration_ms`.
5. Check producer error metric by topic and kind.
6. Verify Kafka broker pods and service DNS.

## Validation Boundary

If no live cluster is available, run the repository validation target:

```powershell
make acs-ingest-kafka-producer-validation-check
```

That command validates the runbook, app config, topic names, unit tests, and
documentation. It does not prove live broker connectivity. Live proof requires
running the consumer and webhook steps above against a real cluster.
